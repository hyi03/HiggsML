# XGBoost 训练进度条设计

## 目标

在运行 `python -m scripts.train_demo --config config/demo.yaml` 时，显示按
boosting round 更新的终端进度条，让用户能确认训练仍在进行，并看到最新的验证集
AUC。

## 方案

使用 `tqdm` 展示进度，并使用 XGBoost 的 `TrainingCallback` 在每轮训练结束后更新
一次进度条。总轮数来自最终生效的 `n_estimators`，因此修改 YAML 配置后进度条总数
会同步变化。

进度条只负责展示，不改变模型参数、训练/验证/测试划分、阈值选择或最终评价逻辑。
验证集继续作为 XGBoost 的 `eval_set`，回调从 XGBoost 提供的 `validation_0`
评价日志中读取最新 AUC，并将其显示在进度条后缀中。

示例：

```text
Training  63%|██████████▌      | 189/300 [validation_auc=0.972]
```

## 组件边界

- `src/progress.py`：提供独立、可测试的 XGBoost 进度回调。
- `src/train.py`：创建回调并传给 `model.fit()`。
- `requirements.txt`：声明 `tqdm` 依赖。

进度回调不保存分析结果。训练完成后的 AUC、KS 距离和过拟合警告仍由现有验证模块
计算并写入 JSON。

## 终端行为与异常

- 正常训练：进度从 0 更新到 `n_estimators`，完成后关闭并保留最终一行。
- AUC 暂时不可用：仍更新轮数，但不显示错误或伪造数值。
- 训练提前停止或抛出异常：关闭进度条，避免终端停留在未完成的动态行；原始异常继续
  向上传递。
- 非交互环境：`tqdm` 仍能安全输出，不影响模型训练和文件产物。

## 测试

先编写失败测试，再实现：

1. 回调每收到一轮训练事件就将进度增加 1。
2. 存在验证集 AUC 时更新后缀。
3. 训练结束时关闭进度条。
4. 训练入口将总轮数正确传给回调。

最后运行完整 `pytest`，并用当前 5,000-entry 小样本执行一次实际训练，确认进度条、
模型文件和验证报告同时生成。
