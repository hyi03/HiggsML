## 1. Executive summary

Sprint M1-03 is the training and qualification sprint of the refactor: it migrates the XGBoost development lifecycle (frame validation, five-fold OOF, candidate training, working-point freezing, final model sealing) and introduces the qualification gate that decides whether a model may be published and test-opening may proceed. The plan's scope (dataset → folds/weights → trainer/OOF → evaluation/qualification → artifacts/CLI), sequencing (TDD training core first, then evaluation/qualification, then artifacts/CLI), and risk controls (spy/deny fixture for test non-access, protocol-driven gates, no post-hoc parameter adjustment) all match the approved design stage 4 and the M1-01/M1-02 review-cycle discipline.

Before execution, the following must be addressed:

1. **[H-1]** The development CSV input schema — the central input contract of this sprint — is not referenced. §5.1 says "校验 19 项特征、metadata、有限性、split 和 forbidden fields" but "metadata" is not enumerated. The committed M1-02 contract (`src/preprocessing/pipeline.py:25-40`) pins `OUTPUT_COLUMNS = (*MODEL_FEATURES, *METADATA_COLUMNS)` with exactly 13 metadata columns (`m4l, label, split, physical_weight, train_weight, channelNumber, eventNumber, runNumber, mcWeight, xsec, kfac, filteff, sum_of_weights`). M1-03's `dataset.py` must validate against this committed schema, and the `m4l` dual role (forbidden model feature, required KS-gate input) must be stated.
2. **[H-2]** The four qualification-gate conditions are not enumerated, and the plan's §1 "等价迁移现有 Angular19 XGBoost 训练行为" is misleading for the qualification gate, which is NEW behavior: the current authority (`src/experiment_runner.py`) has no qualification gate at all — it trains, produces metrics, and saves the model unconditionally. FR-001 R5 and design §9 define four conditions (weighted OOF AUC ≥ 0.80; three ZZ m4l KS ≤ 0.10; signal efficiency strictly > background efficiency per working point; OOF complete, finite, each event exactly once). The plan must list these, cite the protocol fields (`qualification.minimum_weighted_oof_auc`, `qualification.maximum_background_ks`, `qualification.require_signal_efficiency_above_background`), and clarify that the gate is new lifecycle control, not migrated behavior.
3. **[H-3]** Training-weight semantics are ambiguous. The committed M1-02 CSV has a `train_weight` column computed by `src/domain/weights.py::training_weights` as `|w| / mean(|w|)` — a simple mean-normalized absolute weight. But the current training authority (`src/experiment_runner.py:150`) calls `class_balanced_training_weights(fitting)` from `src/full_training_policy.py:75-105`, which normalizes per class to `target = len(frame) / 2` with overall mean = 1. These are different formulas. If M1-03 reads `train_weight` from the CSV instead of recomputing `class_balanced_training_weights` from `physical_weight`, the training behavior will diverge. The plan must state that XGBoost sample weights are recomputed from `physical_weight` at training time and that `train_weight` in the CSV is an audit artifact, not the training input.
4. **[M-1..M-6]** The full-suite verification gate is not pre-registered against the M1-02-recorded failure boundary; the focused `-k` filter silently depends on test naming; the fold algorithm (distinct from the split algorithm) is not pinned; the working-point freezing algorithm is not specified; the final-tree-count rounding rule is not pinned; and the XGBoost protocol consumption is not declared as byte-identical.
5. **[L-1..L-5]** §10 placeholder without the evidence checklist; equivalence policy location not cited; §2 missing FR-001/design references; candidate selection not mentioned; and the `objective`/`eval_metric` provenance is unclear.

No scientific-safety violation was found in the target document.
