## 2. Executive Summary

`sprint-m1-04.md` correctly identifies the one-time `open-test` lifecycle as the next sequential step after M1-03 and appropriately excludes real frozen-run test-opening. However, the plan needs strengthening before implementation: it does not fully enumerate the eligibility conditions the claim must verify, it places the critical "claim before test parse" rule only in risk control rather than implementation tasks, it omits the CLI parameter contract, and it leaves the §10 delivery-evidence section as a placeholder. The focused test command also repeats the naming-dependent `-k` pattern that was explicitly corrected in M1-03. No Critical findings are present; all issues are addressable by document edits before coding starts.

## 4. Overall Conclusion

**Verdict:** Pass with required actions. No Critical findings.

`sprint-m1-04.md` correctly scopes the one-time test-opening sprint and preserves all scientific-safety constraints from `AGENTS.md`, FR-001, and the approved design. Before implementation begins, the plan must:

1. Enumerate the four eligibility conditions in §5.1 and bind them to `config/xgboost_protocol_v1.yaml` fields.
2. Move the "claim before test parse" rule from §9 into §5.1 implementation tasks.
3. Specify the `open-test` CLI as `--development-run` + `--run-dir` only, with explicit rejection of overrides.
4. Declare byte-identical revalidation of the bound preprocessing and XGBoost protocols.
5. Define test scoring semantics precisely and replace undefined `test_reproduced`/`test_nonreproduction` terminology.
6. Add verification of `test_opened: false`, absence of pre-existing `state/test_opening.json`, and `model/model.json` integrity.
7. Require full 32-column schema and compressed/canonical hash validation of `test.csv.gz`.
8. Replace the `-k` focused test command with an explicit file list.
9. Pre-populate §10 with the four required evidence classes and pre-register the M1-03 full-suite baseline.
10. Improve traceability by citing M1-03 review/code-review confirms, FR-001 §R6, and design §6.3/§11.

After these edits, the document will provide a sufficient contract for M1-04 implementation and review.
