## 1. Executive summary

The M1-01 change set is cleanly additive: `git status` shows only `AGENTS.md` and `docs/roadmap/next-stage.md` modified (governance text that correctly records the 2026-09-01 refactor authorization, closing doc-review H-1), with all new code in fresh files. The two console scripts install and behave exactly per design §6 (no `--overwrite`, no science-parameter overrides, only `develop`/`open-test` subcommands), the checked-in protocol values match the legacy authorities item-by-item (verified manually against `config/dsid363490.yaml` and `config/experiment_training.yaml`/`src/experiment_config.py`), and the focused test suite passes (16 passed).

The blocking problems are all in the "strictness" and "baseline" guarantees that this sprint exists to establish:

1. **[H-1]** `src/config.py` rejects unknown keys and bad values only at the YAML top level. Thirteen malformed-protocol variants — unknown nested keys, missing required nested keys, wrong types (`random_seed: "42"`, `subsample: true`, `loose: "0.50"`), non-monotonic working points, out-of-range gates, wrong DSIDs, split fractions summing to 2.7, NaN selection thresholds — were all **accepted** in a live probe. FR-001 R3 and sprint §5.2 require all of these to fail closed.
2. **[H-2]** Sprint §5.1's characterization task list (selection/cutflow, SFOS/Z1/Z2/four-momentum, Base14/Angular5 *values*, identity/split, working points, metrics, qualification, model save/load/predict) is mostly unimplemented; the fold rule is pinned only for determinism even though the test computes the expected hash values and discards them; and there is no record allocating the missing classes to pre-implementation capture, which is the condition review-confirm decision #3 attached to deferral.
3. **[H-3]** The protocol-fidelity test asserts candidate parameters, `folds`, and the qualification gates, but not `working_points` and not five of six `common` parameters; the preprocessing protocol is not compared to `config/dsid363490.yaml` by any test. This was an explicitly accepted required action (review-confirm #6).
4. **[H-4]** `preprocessing_protocol_v1.yaml` omits design-§7.1-mandated content (unit conversion, ROOT tree/field profile, weight semantics, canonical identity, split algorithm) and places `random_seed: 42` under `splitting`, although the legacy stable split (`src/split.py:6-13`) is an unseeded blake2b hash — a behavior-change trap for M1-02.
5. **[H-5]** `RunTransaction.write_bytes` accepts drive-relative paths: `write_bytes("C:evil", ...)` passes every guard, and when the run directory is on another drive, `joinpath` replaces the base entirely (verified: `Path('D:/x/runs/claim').joinpath('C:', 'evil')` → `C:evil`), writing outside the claimed run directory — violating design §11 / FR R7 path-escape rejection on the current platform.

The full-suite baseline reality (211 failed / 737 passed / 1 skipped, all failures pre-existing and environmental) must be recorded verbatim in the sprint delivery evidence, not as a green claim.
