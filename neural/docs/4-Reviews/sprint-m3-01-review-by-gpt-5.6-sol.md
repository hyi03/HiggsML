# Sprint M3-01 文档评审（gpt-5.6-sol）

评审目标为 `docs/1-Requirement/FR-SE-03-subset-bound-discriminant-v2.md` 与 `docs/3-Plan/sprint-m3-01.md`。本评审按 Sprint Workflow 的 document-review gate 检查可执行性，并对照根/Neural `AGENTS.md`、总体开发计划 §7/§13/§16.3/§17 M3、已归档 FR-SE-01/02、当前 `training_subsets.py`、`discriminants.py`、`calibration.py`、`templates.py`、`inference.py` 与 `workflow.py`。范围严格限于 M3 单模型训练与 raw/model-self 血缘原语，不把 M4 批处理或 M6 CDF/确认实现提前纳入。

| Severity | Type | Location | Issue | Evidence | Recommendation |
|---|---|---|---|---|---|
| Critical | Security / provenance | **F-01** — FR-SE-03 需求 2/5–7、§输入、验收 2–3；Sprint §5.1、§9 | 文档只要求把任意传入 DataFrame 的组集合和 weight/mass 摘要与 M2 selection 对齐，不能证明实际用于拟合的特征行来自所声明的 prepared artifact。调用方可保留相同 group、label、行数、`physical_weight`、`m4l`，替换任意分类器特征值，模型仍会携带合法的 `prepared_artifact_id`/subset lineage。validation 也可被替换或删减，只要函数收到的剩余 validation 自洽；“保持完整”没有可信参照。 | M2 membership只绑定 `event_group_id`，summary只绑定 weight/mass/count；`TrainingSubset`拟定 payload 也只含有序组列表和这些摘要。当前 `train_discriminant(frame, ...)` 接受普通 DataFrame，`_validate_frame()`不验证 `event_id`/`source_row_id`、prepared receipt、row identity digest或 payload bytes。FR 又要求 v2 model 正式声明 prepared/population 身份，这会把未经证明的 feature frame 包装成可信 lineage。 | 让 v2 训练从已重新 `read_run` 的 prepared path 内部加载 train+validation payload并应用 selection，或引入只能由该 loader构造的不可变、receipt-bound `PreparedTrainingFrame`，绑定 prepared artifact/file SHA、全量 validation identity digest及所选 train row identity/payload digest。训练前既比较成员/摘要，也比较精确 row identities 与绑定来源；不得让普通 DataFrame 单独取得 v2 身份。增加保持摘要不变但替换 feature、替换 source row、删减/重排 validation 的拒绝测试。
| High | Requirement / interface | **F-02** — FR-SE-03 需求 2–4、§输入；Sprint §5.1 | compact 表示的可信 descriptor 在拟定 v2 调用链中不可获得，同时旧 `candidate/groups/target_lambda` 参数与新 `representation_id` 谁拥有映射没有定义，首个实现必须自行决定是推导、忽略还是比较冲突参数。 | M1 `SampleEfficiencyProtocol` payload只保存三个 representation ID和 freeze artifact ID/digest，不保存 freeze candidate groups/ordered inputs；对象构造后也不保留 `CompactCandidateFreeze`。拟定 `TrainingSubset`“精确 payload”不含 freeze descriptor，新的 `train_discriminant`参数也没有 freeze。当前训练器却必须通过 `candidate='M3', groups=[...]` 才构造 compact输入。默认旧 candidate又是 M3，因此 `decay7`若只给新三参数会与旧默认冲突。 | 将经严格 loader重建的 freeze candidate descriptor（artifact ID、payload digest、representation、groups、ordered inputs、dimension）纳入不可伪造 selection，或把已验证 freeze对象作为 v2 必填参数。明确 v2 分支由 `representation_id`派生 candidate/groups，还是要求调用方同时传入并严格相等；列出对旧 `candidate`、`groups`、`target_lambda` 每种冲突/非默认值的拒绝规则。M3基线应明确 `target_lambda=0`。
| High | Scientific safety | **F-03** — FR-SE-03 需求 10–11、§不纳入范围；Sprint §4、§5.2、§9 | 文档没有要求在现有通用 workflow 上拒绝 v2 的 non-raw calibration 与 assessment inference，可能借“下游兼容”提前开放 M6 的 CDF或使用旧 assessment claim路径读取确认总体。 | 当前 `workflow.py` 的 `calibrate`支持 `raw`、`physical`、`absolute`，`infer`支持 `model_self`与 `assessment`，后者会创建现有 claim并解码 assessment。FR只正面描述 raw calibration/template/model-self propagation，随后笼统说“M3 不增加 assessment”；但一旦 predictor/template接受 v2，自然会流入这些既有分支。M6才拥有 CDF点位、独立 sample-efficiency claim namespace和确认守卫。 | 在 FR 与 Sprint 写出显式阶段矩阵：M3 v2仅允许 raw calibration、普通 template entry和 model-self inference；遇到 physical/absolute transform、assessment/mismatch expectation、freeze/confirmation或 capacity architecture必须在任何相关 payload访问/claim之前拒绝。规定状态/退出码，并加入 monkeypatch 测试证明拒绝发生在 assessment decode和 claim create之前。
| High | Artifact / lineage | **F-04** — FR-SE-03 目标、需求 7–10、§输出；Sprint §5.2 | `research-discriminant-v2` 被称为“发布”的 artifact，但文档只定义 model dict，没有定义承载它的 research run、manifest upstreams或可信读取入口；一个自带 `model_id` 的 dict不能证明其声明的 M2 artifact曾被 receipt验证。M3又明确不加 CLI 参数，当前 train workflow没有输入 subset run的路径。 | 当前 `workflow train` 通过 `ResearchRun`只绑定 prepared upstream，再把 `train_discriminant()`返回 dict写为 `model.json`。FR 输出只列 model dict，未要求 model run的 upstream包含 prepared、compact-freeze、training-subsets，也没有 `read_discriminant_v2_run()`。总体计划 §13要求科学身份由正式 payload与 upstream receipts表达，不能只依赖字段或 `manifest.context`。 | 二选一并在目标/输出中保持一致：若 M3要发布单模型 run，定义一个非 CLI application service/publisher及 reader，规定 `research-run-v1` stage、`model.json` receipt、base/overlay snapshots和 prepared/freeze/subset upstream精确集合；若发布推迟到 M4，就把 M3表述限定为 v2 payload/validator原语，并明确 M4 publisher必须重新验证并绑定这些 upstream，M3 downstream测试不得把自签 dict当来源证明。
| High | Schema / compatibility | **F-05** — FR-SE-03 需求 3、7、9、11；Sprint §5.2 | v2 的“严格”schema没有字段级规范，无法独立实现 reader或判断 unknown/self-consistent tampering；“保留全部 v1 字段”还遗漏了不同 ResearchProtocol版本下条件存在的 `history_contract`。 | 当前 v1 payload包含 architecture/scaler/class means/mass boundaries/state_dict/history/checkpoint/diagnostics等大量字段，`predict_discriminant()`只验证 model digest、ordered inputs、architecture、scaler和tensor，且未按 schema分派。FR只罗列新增 lineage字段，没有规定严格根键集合、类型/有限性、nullable条件、`protocol_id`与base digest关系、`representation`和新 `representation_id`关系、`train_fitted_statistics_source`固定值、参数量公式、state/history/scaler不变量或 v1/v2 unknown schema行为。仅重算 `model_id`不能拒绝攻击者对未校验字段修改后重签。 | 增加 `research-discriminant-v2`字段表：精确必填/条件字段、类型、canonical/finite规则及所有交叉不变量；明确 baseline参数量 `64*d+6657`及 architecture数组、`seed==network_seed`、full/partial nullable规则、`train_fitted_statistics_source`规范值、representation/candidate/groups/inputs映射、base protocol digest和 diagnostics版本条件。reader按 schema显式分派；v2未知/遗漏字段拒绝，v1保持当前历史兼容而不补字段。测试要修改字段并重算 `model_id`，证明语义验证而非外层 digest在拒绝。
| High | Downstream contract | **F-06** — FR-SE-03 需求 10、验收 5；Sprint §5.2 | “统一 lineage 提取/复制/验证”没有给出 canonical lineage对象、函数签名、下游落点和 source artifact绑定，校准、模板与推断可各复制不同子集的字段却仍分别自洽。 | 当前 raw calibration bundle含 model/model_id/candidate/seed/key，template entry只含 mapping_id/candidate_id/seed/prepared ID，model-self inference外层结果主要含 seed而 nested Asimov含 candidate/mapping语义。FR没有列出 lineage的精确键全集（例如 model_id、prepared ID、training-subset artifact ID是否必含）、lineage digest、mapping/threshold/template ID如何覆盖它、template run的多entry upstream约束、inference lineage放在外层还是 nested结果，以及 validator比较的可信 source对象。 | 定义单一严格 `experiment_lineage` schema/不可变对象及 `extract/copy/validate` API；至少绑定 model ID、overlay、prepared/population、training-subset artifact/subset/membership、fraction/draw、network、representation、architecture、experiment/pairing和 transform。规定它在 calibration bundle、每个 template entry和每个 inference result中的精确路径，并让 mapping/threshold/template/result digest及 manifest upstream覆盖它。每层从直接上游重新提取后逐字段等值验证，不接受调用方自由 dict；加入交换同 pairing不同 representation、同 representation不同 subset/model以及跨 run entry的测试。
| Medium | Failure semantics | **F-07** — FR-SE-03 需求 1/3/11、§失败与降级；Sprint §5.1、§6 | loader和参数组失败的异常契约不确定，会导致同一情况在实现中被当作 exit 0科学终态、exit 3绑定错误或普通 TypeError。 | “低统计或缺失/重复 alias 以具名输入/科学终态拒绝”没有分别规定异常类/status/exit code。低统计已有 M2 cell状态 `training_subset_insufficient_statistics`，但缺失/重复 alias表示 schema/binding破坏；三个 v2参数只提供一部分、fraction/draw不在协议、full传入不同 draw的行为也未列明。Neural约定 `ResearchStateError.exit_code=0`、`ResearchError.exit_code=3`，差异是外部可观察契约。 | 列出失败矩阵：低统计 planned cell用何种 `ResearchStateError`状态；缺失/重复 alias、非协议 fraction/draw、部分参数组、伪造 selection、表示/摘要/下游错配分别用何种 `ResearchError.status`和 exit code。说明失败发生在训练/RNG/claim之前，并为每行加直接异常断言。
| Medium | Test completeness | **F-08** — FR-SE-03 §验收；Sprint §5.1–5.2、§7 | 测试清单覆盖名词但未覆盖最容易产生虚假 lineage的攻击方式和兼容边界，尚不足以让 TDD实现具有唯一答案。 | Sprint只笼统写“摘要/协议/表示篡改”“字段篡改”“逐层复制”。没有要求：保持组与摘要不变的 feature/source-row替换；完整 validation的可信对照；只提供部分 v2参数；旧 candidate/groups与 representation冲突；整数/浮点 full与任一 alias规范化；更改字段后重算 model/downstream digest；v2进入 CDF/assessment时 claim-before-decode拒绝；v1在所有现有 protocol/history变体和 positional/keyword调用下 byte-for-byte不变。 | 将这些场景加入 focused matrix；对 train-derived统计用可计算小 fixture精确断言 scaler、class means、mass bins、threshold和 fitting rows只来自 subset，同时验证 validation AUC/early stop使用完整 bound validation。v1兼容应保存调用前基线 payload bytes/model ID并比较，而不只检查可预测或 schema名称。
