# Sprint M2-01 文档评审（gpt-5.6-sol）

评审范围为 `docs/1-Requirement/FR-SE-02-deterministic-training-subsets.md` 与 `docs/3-Plan/sprint-m2-01.md`，并对照根/Neural `AGENTS.md`、已完成的 FR-SE-01/M1 契约、`docs/sw-dev/h4l-compact-kinematics-sample-efficiency-development-plan.md` §6、§13、§16.2、§17 M2、`docs/sw-dev/artifact-schema.md`，以及当前 `h4l-events-v1`、`ResearchRun`/`LoadedRun` 和 sample-efficiency protocol 实现。评审只判断 M2 的确定性训练子集 artifact；不把 M3 训练、M4 批处理或正式科学运行纳入本 Sprint。

| Severity | Type | Location | Issue | Evidence | Recommendation |
|---|---|---|---|---|---|
| Critical | Correctness | **F-01** — FR-SE-02 §影响范围、需求描述 2/5；Sprint §5.1 | 输入访问规则与当前 prepared 数据格式直接矛盾，按文档无法同时生成规定摘要并保证“不解码 payload”。文档还要求验证“每行 identity digest”，但当前行格式没有该字段。 | 当前 `src/research/data.py` 的 `IDENTITY` 精确为 `event_id, source_row_id, event_group_id, split, dataset, label, role`；`write_research_data()` 把 `physical_weight`、`m4l` 写在制表符后的 payload。FR 第 32 行却称二者由 identity envelope 提供，而第 24、29 行禁止解码任何 payload。`h4l-events-v1` 只有整文件 manifest receipt，未发布逐行 identity digest。上位计划 §6.1 的边界是读取 train 身份和“必要统计”、不读取 assessment payload，并未要求所有角色 payload 都不可解码。 | 在实现前选择并写死一种可执行契约：优先明确允许在完成 header、identity、role-hash 和 receipt 校验后，仅解码 `role=train` 的 payload 以读取 `physical_weight`/`m4l`，其余角色（尤其 assessment）永不解码；或另行设计有 receipt 的 identity/stat sidecar/新版 events schema。不得原地改变 `h4l-events-v1`。删除不存在的逐行 digest 要求，或定义其字段、计算字节和验证来源。加入 train 必要统计可读、assessment 非法 payload 仍成功、非-train payload 不被访问的测试。
| High | Artifact contract | **F-02** — FR-SE-02 需求描述 4/5/7、§输出；Sprint §5.1–5.2 | 三个 payload 的字段全集、canonical bytes、ID/digest 计算边界和交叉引用没有规范，reader 的“重算所有 ID/摘要/ledger”因而没有独立判据。FR 还新增 membership/ledger 两个 schema ID，而上位计划 §13.1 只登记一个 `h4l-training-subset-plan-v1` 来承载成员资格、嵌套关系和 ledger，版本边界不一致。 | `subset_id`、`membership_digest`、membership 行的 `membership hash`、`draw_or_full`、fraction 的 JSON 数值表示、plan/ledger entry key 与排序、成功/失败 entry 是否进入 membership，均未给出计算公式。当前 `artifact-schema.md` 明确说精确字段以 reader 常量为准，但 M2 reader 尚不存在，不能让首个实现反向定义规范。上位计划 §6.4 只给出文件职责，§13.1 只列 `h4l-training-subset-plan-v1`。 | 在 FR 中增加三个 payload 的规范字段表，逐项定义严格键集合、类型、状态枚举、排序和 canonical JSON/JSONL 编码；明确 `subset_id` 与 `membership_digest` 的 preimage（是否含 prepared ID、overlay digest、fraction、draw/full、label、成员行、摘要），以及 ledger 如何引用 full 去重项。决定是一个 schema 跨三文件还是三个独立 schema，并同步 `artifact-schema.md` 和 Sprint 的明确文件清单。为未知字段、重复 JSON key、NaN/Infinity、重排、跨文件替换和可重算 digest 加负向测试。
| High | Binding / provenance | **F-03** — FR-SE-02 需求描述 1/7、§输入；Sprint §5.1、§9 | “已验证 overlay/freeze”“完整 upstream 绑定”没有可执行的来源与发布契约；仅把 prepared 放进 `ResearchRun.upstreams` 不能满足上位计划要求的双协议和 compact-freeze trust chain。 | M1 明确声明 `SampleEfficiencyProtocol`/`CompactCandidateFreeze` 只校验内存 payload，自身不验证 manifest receipt，调用方传入的 artifact ID 也不证明来源。当前 `ResearchRun` 只把一个 base `protocol` 写成 `protocol.json`/`protocol_sha256`，`upstreams` 只接受 `LoadedRun`；`read_run()`也只按该 base protocol 验证。FR 第 34 行只要求 manifest 上游包含 prepared，且输出列表没有 overlay snapshot、freeze snapshot或其 receipt。上位计划 §6.4/§13.1 要求 prepared、base protocol、sample-efficiency protocol、compact freeze 都通过正式 payload 和 upstream receipts 表达，不能只放 `manifest.context`。 | 明确 M2 API 接收的 overlay/freeze 来源：要求可验证的发布 run/文件 receipt，或把创建并验证该发布 artifact 纳入 M2。规定输出必须保存哪些 snapshot 文件、各自 schema/digest/artifact ID、它们在 `training-subsets.json` 与 manifest upstream 中的精确绑定，以及 reader 如何从可信来源重载后重新构造 M1 对象。若继续用 `research-run-v1`，把双协议绑定放在正式 payload和受 receipt 保护的 snapshot 中，不改变 v1 manifest digest 语义，也不依赖 `context`。
| High | Scientific semantics | **F-04** — FR-SE-02 需求描述 5/6；Sprint §5.1–5.2 | 摘要和低统计门的数学定义不完整，并引用了 M1 overlay 中不存在的“mass support”阈值。不同实现会得到不同 `sumw2`、`neff_abs`、终态和 digest。 | FR 只列 signed/absolute/sumw2/neff/m4l range，没有说明按行还是先按 `event_group_id` 聚合、使用 signed `physical_weight` 还是 role-corrected `yield_weight`、每类还是总体应用 `min_effective_count`。现有 `grouped_statistics()` 的 `sumw2` 是事件组内权重先求和再平方求和；现有 research trainer则使用逐行 `abs(physical_weight)`。FR-SE-01 的 `subset_algorithm` 只冻结 `min_groups_per_label` 和 `min_effective_count`，没有 mass-support 阈值或算法 ID。 | 在 FR 中给出每个摘要量的公式和计算顺序，尤其规定同组多行的 signed sum、absolute support、`sumw2` 与 `N_eff_abs`，并明确门是逐 label 还是总体。将所有门严格限制为 overlay 已冻结的字段；如 M2 确需质量/mass support，先以新版受审 overlay 字段和算法 ID 冻结，不能从数据临时选择，也不能借用 M3 的 11-bin 训练前提。
| High | Failure semantics | **F-05** — FR-SE-02 需求描述 6、§失败与降级；Sprint §5.2、§6 | 子集级科学终态、run 级状态与异常分类没有分开；同时把非有限权重列入 `training_subset_insufficient_statistics` 会把损坏输入降级成正常科学终态。 | 一个 plan run 可同时包含可用和低支持 subset。FR 说低统计“记录 ledger 终态”，但未说明 manifest 是否仍为 `complete`、reader 是否返回可用项、失败 subset 是否有 subset ID/membership，或何时抛 `ResearchStateError`。当前 `ResearchRun` 只有抛 `ResearchStateError` 才以 exit 0 发布非-complete 状态，而默认 `read_run()`拒绝非-complete run。当前 `load_research_data()` 对非有限 numerical columns 抛 `ResearchError`；上位计划 §14 将 `training_subset_binding_mismatch` 定为输入/绑定失败。 | 定义 plan entry 状态机与 run 状态：建议所有预定项均入 ledger，有限但不足支持的项为 `training_subset_insufficient_statistics`，其余项仍可发布；run manifest 保持可被标准 reader 消费的明确状态。规定失败项是否发布 membership/ID及其摘要。把 NaN/Infinity、字段缺失、receipt/identity/协议不一致归入 exit 3 的绑定失败；只有经过验证的有限数据出现空类别、零支持或未达冻结阈值时才记录科学终态。为混合成功/失败计划、全失败计划和篡改后读取分别断言 manifest status、entry status、异常类/status/exit code。

上述问题修正后，文档对 M2 边界的其余部分与仓库约束一致：事件组不拆分、按 label 的确定性嵌套前缀、100% `full` 去重、三表示共享成员资格、MC-only、assessment 隔离、旧 run 不修改，以及 Windows synthetic 证据不替代 ARM64/ROOT 验证。
