# Sprint M5-01 文档评审（GPT-5.6-sol / high）

评审范围为 `FR-SE-05-paired-aggregation-reporting.md` 与 `sprint-m5-01.md`，并对照样本效率开发总计划、已归档 M4 合同、artifact schema、SampleEfficiencyProtocol 及仓库科学安全约束。本次仅做静态文档评审，未运行测试或读取研究数据。

| Severity | Type | Location | Issue | Evidence | Recommendation |
|---|---|---|---|---|---|
| High | Statistical correctness | `FR-SE-05`「评价事件组 bootstrap」「聚合与误差分层」「Q* 与渲染」 | 将各 cell 的 bootstrap `std` 取均值不能作为聚合 AUC 曲线点的不确定度，也不能形成有统计含义的误差带；该做法丢失了文档特意要求的跨模型、跨 cell 共同 replicate covariance。 | FR 要求所有 complete models 共用每个 replicate 的 event-group multiplicity，但 summary 又把 `evaluation_uncertainty` 定义为“cell bootstrap std 的均值”。一般有 `sd_b(mean_cell AUC_{cell,b}) != mean_cell sd_b(AUC_{cell,b})`，尤其共同重采样使 cell 间相关。总计划 §9.2 将它定义为独立的评价事件误差，而 FR 的 PNG 段又允许把误差层画在聚合曲线上，容易把“典型 cell 波动”误报为曲线均值误差。 | 冻结两种语义之一：若要画聚合 AUC 误差，应逐 replicate 先按该 curve row 的固定 cell 集合聚合，再由 replicate-level aggregate 计算 mean/std/quantiles，并保留或绑定可重放的 replicate 摘要；若只保留 `mean(cell std)`，字段改名并明确它只是描述性 sensitivity，禁止作为聚合均值误差条/带。对 W68继续明确 evaluation bootstrap 不适用。 |
| High | Schema / executability | `FR-SE-05`「报告合同」「聚合与误差分层」「Q* 与渲染」「Reader 与完整性」; `sprint-m5-01` §4 | 文档声称 exact schema 和全链重放，但只列出了 record 顶层字段；summary、curve row、Q* result、uncertainty 对象、report-contract 的 schema-version 映射以及 CSV 列均没有精确结构、类型、枚举、nullable 条件或数值域。实现者无法唯一实现，reader 也无法按合同拒绝未知/缺失/非有限字段。 | `sample-efficiency-summary.json` 只被描述为按三键聚合“计数、failure rate、均值和误差层”，未给 exact keys；successful `pair_status` 的值未定义；bootstrap 在 `not_estimated`/仅一个 valid replicate 时 mean/std/quantile 应为 null 还是数值未定义；Q* 只有状态文字，没有 result schema、插值输入 IDs、估计值字段或 ID；CSV 只说包含“聚合指标/误差状态”。这与 reader 必须重算 IDs、聚合和 CSV 逐值的要求不相容。 | 在编码前加入完整版本化 schema 表或 JSON Schema：所有对象 exact keys、类型/范围、有限值、状态枚举及逐状态 nullability；定义 canonical ordering、每层 ID preimage、JSONL 是否有 header、CSV 固定列/数值格式/newline、Q* 输出和 report-contract 的 schema-version map。Sprint 将这些 schema 文档列为首个可验收交付，而不是留给实现自行决定。 |
| High | Terminal-cell completeness | `FR-SE-05`「报告合同」「聚合与误差分层」; archived `FR-SE-04`「状态机与完整性」 | `actual_train_group_count` 的权威来源对 model-stage terminal cell 不可执行。FR 要求所有 planned cell（含 terminal）都有该字段并按它聚合 failure rate，却规定它来自 model `training_summary_total`；M2 低统计或训练前终止的 cell 没有 model artifact。 | M4 合同允许 `training_subset_insufficient_statistics` 在 model stage 终止，stage artifact 全为 null，但 training-subsets summary 仍有 `summary_total.group_count`。M5 文档仅说组数“来自模型并与同一 subset summary 重验”，没有 terminal fallback。若写 null，便违反 record 字段和 summary 三键；若删除该 row，又违反完整 ledger 保留。 | 对所有 cell 以已重验 M2 subset `summary_total.group_count` 为权威值；model 存在时再要求 `model.training_summary_total.group_count` 与其相等。规定它始终为正整数或明确允许零的 terminal 规则，并让 terminal cell 继续进入相同 `(representation,fraction,actual_count)` 的计划分母和 failure count。 |
| High | Bootstrap reproducibility | `FR-SE-05`「评价事件组 bootstrap」; `FR-SE-01` `evaluation_uncertainty` contract | “排序后 unique group + seed + 有放回抽样”不足以保证跨实现、跨平台或 reader 重放得到同一 bootstrap 和统计量。 | 未冻结 group ID 的排序编码、RNG/bit-generator（如 PCG64）、随机整数调用方式、replicate 编号、AUC 实现与 signal label、score ties、样本标准差 `ddof`、16/84 分位算法，也未定义 partially-estimated 只剩一个 valid replicate 时 `std` 的状态。FR-SE-01 只为 noninferiority CI 固定了 linear quantile；没有把该规则自动授予 M5 evaluation bootstrap。仅记录 seed/repeats 无法唯一重放。 | 定义版本化算法：canonical group-ID bytes 和排序、固定 bit-generator/API、每 replicate 的 multiplicity 生成顺序、`label=1` 与 sklearn weighted AUC 语义、valid 判据、`ddof=1`、quantile method，以及 0/1 valid replicate 的精确 null/status。最好发布或摘要绑定一个 batch-level resample-plan ID，使所有 cell 必须引用同一计划；加入小型 golden multiplicity/AUC/quantile 向量测试。 |
| High | Trusted reader boundary | `FR-SE-05`「范围与约束」第2、5项、「Reader 与完整性」; archived M4 `LoadedLearningCurveBatch` API | “先经 M4 reader 重验，再读取 cell payload”没有定义可信对象如何跨越第二次读取。当前 M4 reader 返回 batch path/run/plan/ledger/summary，不返回已验证 model、inference 或 prepared-validation handles；M5 若随后直接按路径读 JSON，可能绕过 stage reader/receipt，或在验证与使用之间读取变化后的文件。 | M4 `LoadedLearningCurveBatch` 只有 `path, run, plan, ledger, summary`；其 reader 内部虽重验所有 stage，但关闭后不把 `LoadedRun`/verified model 暴露给 M5。M5 又必须重新取得 model scores、model payload、inference payload和 prepared validation 数据。FR 只说 report manifest 的直接 upstream 为 batch，并未指定 cell reopen API、artifact-ID compare 或 payload-use-time receipt recheck。 | 冻结一种边界：扩展 M4 verified result，提供不可伪造的 cell artifact handles/读取服务；或要求 M5 对每个 pointer 调用 M3/M4 public reader重新打开对应 run、核对 ledger artifact ID/path/stage/upstreams，并在实际预测/取值时再次验证 receipt。prepared validation 必须通过 identity-first、`allow_assessment=False` 的 role loader进入。测试在 M4 read 后、M5 payload use 前替换文件必须被拒绝。 |
| High | Q* scientific validity | `FR-SE-05`「聚合与误差分层」「Q* 与渲染」; `SampleEfficiencyProtocol.quality_target` | Q* 规则没有定义 curve point 的完整性门槛，也没有处理不同 fraction 因 floor rounding 得到相同 `actual_train_group_count` 的情况；因此可能用少数幸存 cell 的均值宣称达到目标，或在重复横坐标间得到不唯一的“相邻点”。 | 均值只使用 complete values，而 failure rate 单独报告；文档未要求全部或预注册比例的 draw×network cells complete。若失败与性能相关，survivor mean 会产生选择偏差。M2 按 label 对 fraction 取 floor，严格递增 fraction 并不保证实际组数严格增加，尤其 synthetic/小总体；summary 又保留 `(fraction,actual_count)` 两个键。Q* 段只在插值时要求相邻实际组数增加，没有规定重复 n 的合并/拒绝、缺失点、exact equality 的数值规则或不完整 row 的状态。 | 在协议/合同中预注册 Q* eligibility：建议每个候选点要求全部计划 cell complete，或新增不可事后修改的最小 completeness 门槛；不满足时输出具名 `not_estimated_incomplete`。规定重复实际 n 必须合并为一个以相同 membership 证明的点或使 Q* 不可估计，冻结排序/tie/equality tolerance 和线性公式，并在输出记录所用相邻 curve-row IDs。覆盖重复 n、terminal-survivor bias、非单调多 crossing 和精确命中测试。 |
| Medium | Uncertainty decomposition | `FR-SE-05`「聚合与误差分层」 | subset uncertainty 在各 draw 使用不同的“可用 network seed”均值时，会把网络随机性与缺失模式混进 draw 波动；relative/delta 的 uncertainty 是否基于严格配对值也没有冻结。 | 文档允许任意 terminal cell，随后规定“先对同一 draw 的网络 seed 取均值，再跨 draw 做样本标准差”，且所有均值只使用 complete 值。若 draw A 只剩 seeds 42/43、draw B 只剩 44/45，得到的差同时包含 subset 与 network 效应。对 `relative_w68`/`delta_w68` 若先分别汇总表示再相减，也会丢失 M1 已冻结的 seed/draw pairing。 | 对 subset layer 使用所有 draw 共同 complete 的 network-seed intersection，少于预注册最小共同 seed 数时 `not_estimated`；或要求完整 seed block。network、subset 的 delta/relative uncertainty直接从 record 中已配对的 delta/ratio计算。每层记录 planned/eligible/used draw 与 seed 数、具体 ID 集合及状态，不能只给一个标准差。 |
| Medium | Pairing contract | `FR-SE-05`「报告合同」配对段; `sprint-m5-01` §5; archived M4 plan/reader | 配对规则没有使用已存在的 `pairing_id`/subset identity，而且 Sprint 要测试“缺 baseline 保留”，与“只接受 M4 完整 reader”矛盾。 | M4 plan 对每个 representation 都提供同一 pairing cell 的 `pairing_id`、`training_subset_id` 和 membership binding；M5 record也保存 `pairing_id`，但比较只列 fraction/draw/network/architecture。合法 M4 plan 缺少 engineered19 cell 时会被 M4 reader 以 `learning_curve_incomplete` 拒绝，报告层看不到这种“缺 baseline”；它只能看到 baseline planned 但 terminal。successful `pair_status` 与 `baseline_experiment_cell_id` 在 terminal 时是否仍记录 planned ID也未定义。 | 要求 representation 与 engineered19 的 `pairing_id`、training subset ID及显式 pairing keys全部一致；不一致是 binding failure，不是 missing pair。定义成功状态（如 `paired`）和 terminal counterpart 的 `paired_cell_missing`，并规定 baseline planned cell ID始终记录。把“缺 baseline”publisher测试改为“M4 reader拒绝不完整 plan”，纯聚合器只需对 terminal baseline测试保留行为。 |
| Medium | Human-output integrity | `FR-SE-05`「Q* 与渲染」「Reader 与完整性」 | Reader 对 PNG 和 Markdown 只要求 receipt 存在，无法发现 receipt/manifest 自洽重签后的误导性图形或越界科学表述，与“任何语义漂移均拒绝”和仓库 claim 边界不一致。 | CSV 要求逐值重放，但 PNG/Markdown 明确只检查 receipt；攻击者可以保持 verified JSON/CSV 不变，替换图或文字后重算 receipt、manifest artifact ID，reader 仍会返回一个“已验证报告”。Markdown 又是承载失败表、Q* 状态和非 ATLAS 声明的主要人类输出。 | Markdown 使用固定模板从 verified summary/records 精确重放并比较 bytes。为 PNG 冻结 plot-spec（panel、series、point IDs、error-layer semantics、缺失断线、轴标签、claim scope）及其 digest；可采用固定 renderer 后比较像素/文件摘要，或明确把 PNG 标为非权威视图并让 reader只认证 plot-spec/CSV、验证 PNG 嵌入的 contract/CSV digest。加入语义替换后完整重签的负例。 |
