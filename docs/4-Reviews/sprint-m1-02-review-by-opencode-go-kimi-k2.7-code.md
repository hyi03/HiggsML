## Executive Summary

The revised `sprint-m1-02.md` and the new `preprocess-protocol-v1.md` resolve the two Critical blockers from the previous review round:

1. **Golden authority is pinned.** The per-column golden is fixed to the r3-ARM64 enrichment table `xgboost/runs/angular5-mc-363490-2026-08-26-r3-arm64/processed/mc_events_angular5.csv.gz` at SHA-256 `bc31f4e65ccecc0a1962648cfe240b67d8ecc6df8eda2478b3f46c93d2f34f09`, together with its identity and baseline lineage manifests.
2. **Equivalence policy is pinned.** Structural fields are compared exactly; floating-point columns use element-wise `isclose(rtol=1e-12, atol=1e-12, equal_nan=False)`; the authoritative full-data gate runs only on the locked native `osx-arm64` `pytorch` environment.

`preprocess-protocol-v1.md` is now a self-contained scientific annex: it specifies the two per-sample ROOT profiles (tree, unit, branch mappings), the 19-stage cutflow, all selection thresholds and boundary semantics, MC normalization and weight formulas, canonical identity, stable train/validation/test split, Base14/Angular5 construction (including degenerate-geometry fail-closed rules), deterministic row/column order, canonical CSV serialization, golden comparison procedure, and artifact schemas.

**Overall verdict:** The Sprint and protocol are now **decision-complete for implementation**, **scientifically safe**, and **internally consistent** with `FR-001`, the approved refactor design, and both `AGENTS.md` files. The remaining findings are clarity/consistency improvements; none block implementation.

- **Sprint ↔ Protocol:** `sprint-m1-02.md` correctly treats `preprocess-protocol-v1.md` as the normative scientific source (§3 "协议内容门", §6, §7). The Sprint's scope, out-of-scope items, acceptance criteria, and implementation order are consistent with the protocol.
- **Protocol ↔ FR-001:** The protocol satisfies FR-001 R2 (MC-only, SHA-bound inputs, no CLI override of scientific rules), R6 (manifest/canonical-hash artifacts), and R7 (tests and documentation). The golden SHA-256 and tolerance in FR-001 R2 match protocol §7.1–§7.2 exactly.
- **Protocol ↔ Design:** The design's 19 output features, 15 classifier features, 199,104 target rows, and deferred five-fold development split are all preserved in the protocol. The design's high-level statements are now grounded in protocol-level constants.
- **Protocol ↔ `xgboost` source (read-only characterization):** Spot checks confirm the protocol faithfully transcribes the legacy behavior:
  - Branch mappings match `xgboost/src/input_profiles.py`.
  - Selection thresholds and boundary semantics match `xgboost/src/selection.py`.
  - Weight formulas and ZZ override constants match `xgboost/src/weights.py` and the r3-ARM64 run configs.

### 3. Scientific Safety

- **MC-only:** Only Higgs 345060 and ZZ 363490 are accepted. Unknown samples, extra paths, DSID 700600, and real-data paths are required to fail closed with exit code 3 (§1, §2.1, §2.2).
- **Forbidden features:** `m4l`, identifiers, provenance, split, and weight columns are excluded from the 19 model-candidate features; the protocol explicitly notes that only the approved 15 features may enter the classifier in later sprints (§6.1).
- **Blinding / test discipline:** The protocol defers five-fold development fold definition to M1-03/M1-04 and never reads test features during preprocessing (§5.3).
- **Immutable golden:** Differences must be explained and escalated to design review; the golden must not be updated to mask differences (Sprint §5.3, §6; protocol §7.2).
- **No `xgboost/src` runtime dependency:** Both the Sprint and protocol state that `xgboost/` is read-only characterization/golden evidence (Sprint §2; protocol §1).

### 4. Self-Containedness

`preprocess-protocol-v1.md` is now self-contained for the M1-02 preprocessing scope. An implementer reading `sprint-m1-02.md` + `preprocess-protocol-v1.md` + `neural/AGENTS.md` can implement the preprocessor without guessing or inspecting real data. Cross-references to `FR-001` and the design document are appropriate for broader context but are no longer required to resolve ambiguities.
