## 3. Focus-area assessment (per review request)

1. **Two-stage held-out router** — PASS with one High finding. Routing is correct: the table is hash-bound (file SHA-256 + size + decompressed canonical-content SHA-256) before any routing; header must match exactly; the `split` token is located by comma scan, which is safe because all 21 preceding fields are canonical `.17g` floats (no commas possible) and string columns reject CSV specials; `split=test` rows are counted and skipped before any other token of the row is decoded; unknown/empty split fails before decoding the rest of the row; the poison-token test passes, and a mistakenly included test row would fail numeric decoding (`dtype=float64`). Test-row identities/labels/weights/features are never recorded — only the not-opened count.
2. **Manifest/path/hash binding** — PASS except H1 (root confinement) and M1 (preprocess protocol/config payload SHAs not surfaced/validated). Output record set, per-record schema, per-component symlink/junction/reparse rejection (for descendants), file size + SHA-256, and canonical-content SHA are all verified fail-closed before routing.
3. **OOF completeness/order/identity** — PASS. Per-candidate contract (columns, row count, lambda binding, fold binding, field equality, identity uniqueness, score finite in [0,1]) is validated pre-publication; publication order is protocol lambda order then `source_sample` UTF-8 bytes then `source_entry` ascending (verified in the synthetic E2E); gzip file and canonical-content SHAs recorded; development-frame equality binding excludes test identities by construction.
4. **Weighted qualification math and fail-closed** — PASS. Weighted AUC uses `train_weight`; thresholds use descending stable sort of background scores with cumulative `abs(physical_weight)` and first `>= target*total` (inclusive full tie, achieved may exceed target); efficiencies and KS use `abs(physical_weight)`; KS is a right-continuous weighted two-sample empirical CDF max-difference on the union of mass values and fails on empty/non-positive inputs instead of returning 0; gate comparisons use no epsilon with correct equality semantics (AUC `== 0.80` passes, KS `== 0.10` passes, signal efficiency `== background` fails); tie-break is best-AUC-relative `atol=1e-6` then smallest lambda and avoids chained-tie non-transitivity (covered by test).
5. **Final fixed-epoch fit** — PASS. Full-development scaler (float64, population variance), seed 42 re-initialization of the full 9,228-parameter model and AdamW, same batch/shuffle/lambda-schedule/loss contract, exactly `final_epochs` = sorted fold-best-epoch median (third of five integers, no rounding), no validation/checkpoint/early-stopping, non-finite fail-closed, payload binds protocol SHA, feature tuple, selected lambda, seed, epochs, and scaler. Test gap noted (L6).
6. **Transaction publication ordering/layout** — PASS. Staging directory under the allowed root, atomic rename publish, never overwrite; manifest written last and covering every published file except itself; eligible-only `model/model.pt` + `model/scaler.json`; `no_eligible_candidate` publishes full evidence without any model/test-opening placeholder; abnormal runs publish `failure.json` and no success manifest; non-overwrite/allowed-root semantics covered by the pre-existing `test_transaction.py`.
7. **Canonical artifacts** — PASS. `canonical_json_bytes` (UTF-8, `sort_keys=True`, `separators=(",", ":")`, trailing LF, `allow_nan=False`) is used exactly for the three sealed JSON files (byte-exact verified); the M1-02 indented `json_bytes` helper is untouched; CSVs use fixed column order, LF, `.17g`; gzip is compresslevel 9 with `mtime=0`. `fold_metrics.csv` is not byte-reproducible across runs because the sealed epoch schema embeds wall-clock timing fields (by design; noted as Info).
8. **CLI exit mapping** — PASS. 0 for success and `no_eligible_candidate`; 2 for argparse usage (tested for `develop` missing args); 3 `InputBindingError`; 4 `RunPathError`; 70 unexpected (all tested). Logging/UX gap noted (L7).

## 6. Conclusion

The M1-04 implementation is a faithful, fail-closed realization of Development Protocol V1 in the audited areas: two-stage held-out routing, OOF completeness/order, weighted qualification mathematics, the fixed-epoch final fit, transactional publication, canonical artifacts, CLI exit mapping, and protocol sealing all check out, and the full test suite plus an un-mocked synthetic end-to-end run pass on Windows.

One **High** finding (input-run allowed-root confinement bypass via `..`) should be fixed before this change set is merged, since it violates a sealed binding requirement and is cheap to fix. The four **Medium** findings are requirement/test-gate gaps (preprocess protocol/config hash surfacing, reader mutation tests, an un-mocked end-to-end test, OOF mutation completeness) that should be closed before sprint sign-off per §10's minimum test gate. **Low/Info** findings are hardening and hygiene items that can be scheduled normally.

Recommendation: **request changes** (fix H1; address M1–M4), then re-run the focused and full suites. Nothing in this review constitutes or authorizes test-opening; all evidence is synthetic and Windows-based, and the authority gate remains M1-06 on locked native `osx-arm64`.
